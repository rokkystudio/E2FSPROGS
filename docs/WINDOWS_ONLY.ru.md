# Квалификация беты без Linux

**Принцип:** весь процесс должен выполняться на Windows x64. Никакие проверки не требуют установки Linux, WSL, виртуальной Unix-машины или обращения к удалённому Unix-серверу.

- **Сборка:** MinGW-w64 GCC и Windows-хостовая оболочка MSYS2 используются исключительно как *инструменты разработки*. Выходные PE EXE работают независимо от MSYS2 DLL и имеют только системные Windows-импорты.
- **Проверка файловой системы:** независимый `tests/ext4_independent_reader.py` использует только стандартную библиотеку Python для чтения суперблока, дескрипторов групп, inode, extents глубины 0 и содержимого файлов в корне ext4. Он сравнивает SHA-256 с исходным файлом без вызова debugfs для проверки.
- **Проверка операций:** `tests/test_independent_windows.py` создаёт одноразовые ext4-образы с блоками 1024/2048/4096 байт. Все 6 сравнений исходных бинарных файлов с содержимым, независимо прочитанным из образов, прошли.
- **Другие тесты:** `tools/run_beta_tests.cmd` запускает проверку форматирования, сохранения размера, записи/извлечения, исправления суперблока и inode, а также защиту от записи в `shared_blocks`.

**Ограничение независимого парсера:** вложенные каталоги, деревья extent глубины больше 0, сжатые или неинициализированные extents и часть ext4 features не поддерживаются; парсер завершается явной ошибкой. Это не полный независимый аудит всей ФС.

**Статус:** Windows-only тестирование не требует Linux. Но завершение автоматических тестов не доказывает безопасность прошивки Android: отдельно необходимы проверка реальной `shared_blocks`-метаинформации, AVB/dm-verity, подтверждённый откат и проверки больших образов. Прошивка пока запрещена.

### Отрицательные тесты
Набор tests/test_independent_negative.py проверяет отказ при ошибочном magic, невозможном размере блоков, испорченном заголовке extents и отсутствующем имени файла: 4/4 PASS. Это не эквивалент полного fsck.
